# Every source file that writes a product AND names baseRetail as a key (GAP-06,
# rule 65). __tests__/retailWriters.test.ts scans src/ and fails when this list
# and the code disagree, in either direction.
#
#   <path> | <kind> | <baseRetail keys> | <reason>
#
#   writer       goes through lib/pricing/retailWriter.ts for an EXISTING
#                product's retail (applyRetailChanges, or retailFieldsForImport
#                + recordImportPriceChanges). Must import it.
#   create-only  writes baseRetail only on a product it is creating -- nothing
#                to lock or ledger yet. The reason says why.
#
# The count is how many times the file names baseRetail as an object key
# (`baseRetail:`, `"baseRetail":`, `["baseRetail"]:`, shorthand `baseRetail,` or
# `{ baseRetail }`, or an assignment `x.baseRetail =` / `x["baseRetail"] =`),
# selects (`baseRetail: true`) aside. It is a ratchet: a new one -- say a raw
# `baseRetail: price` slipped back into an importer's update -- fails until a
# person looks and updates this line. Interface fields and response shapes in
# the same file count too; that is the price of a check that cannot be argued
# with.
